# 交易模型证伪记录 / Trading-model falsification journal

这个目录只做一件事：把"交易里被当作正确模型的说法"逐条写成可检验的主张，然后用可复现的计算去**尝试推翻它**。推翻不了就如实写"证据不足"，不把没验证过的结论留成默认正确。

它对应两类东西：

- 本仓库自己的工具与方法里隐含的模型（定价口径、年化口径、回测假设、共识投票假设等）；
- 广泛流传但没被检验过的交易经验（"高胜率所以稳赚"、"年化展期收益就是能拿到的收益"、"平价没残差就是无套利"等）。

> 边界：本目录是研究记录，不是交易信号，不构成投资建议。所有结论只对写明的输入、参数和口径成立。

## 状态定义

| 状态 | 含义 |
|---|---|
| `OPEN` | 已登记，尚未测试 |
| `REFUTED` | 在写明的口径下被反例推翻（"主张不成立"） |
| `SUPPORTED` | 在写明的口径下测试通过（"未发现反例"，不等于普遍成立） |
| `AMBIGUOUS` | 测试结果依赖口径/数据，无法给出单一结论，记录分歧点 |
| `BLOCKED` | 缺少数据或权限，写清缺什么、解除条件 |

## 每轮协议

1. **先登记，后计算**：在 `rounds/<日期>.md` 顶部写清楚主张、操作化定义、判定规则、输入和参数，再跑计算。禁止先看结果再挑口径。
2. **可复现**：给出精确命令、输入文件/参数、Python 版本；只用本仓库已有工具或标准库。结果里的每个数字都能从命令重算。
3. **交叉验证**：关键数字尽量用第二种方法复核（例如：仓库工具 vs 独立公式实现；解析解 vs 数值）。两种方法必须给出一致的值，否则记录差异。
4. **写明边界**：模型落地的是"在哪些假设下成立/不成立"，不是"市场一定如何"。模型型证伪与经验型证伪分开标注。
5. **一轮一条**：每轮只推进一个主张，避免把多个结论混在一起。
6. **更新登记表**：轮次结束后更新 `claims.md` 的状态、轮次、证据链接；没有变化也要写"本轮未产生新结论"。
7. **代码缺陷的处理**：如果证伪过程暴露的是本仓库工具的 bug，不在本目录里改代码，另开 issue（附复现与 file:line）。

## 防作弊规则

- 不使用未来数据；任何回看窗口必须写明起点，不能事后调整。
- 涉及成本的测试必须建模成本（手续费/滑点/换手），并单独报告"零成本"与"含成本"两列。
- 多个参数/窗口/标的被尝试过时，必须报告尝试次数，不能只贴最好的那个。
- 数据来源与获取日期必须记录；合成数据要明确标注 `synthetic`。
- 不把"测试通过"写成"策略有效"；`SUPPORTED` 只表示未发现反例。

## 目录结构

```
falsification/
├── README.md            # 本文件：协议与规则
├── claims.md            # 主张登记表（唯一索引）
└── rounds/
    └── YYYY-MM-DD.md    # 每轮一条主张的完整记录（含命令与输出）
```

## 节奏

由 DSH 定时任务「交易模型证伪轮」在**每周二、周五 21:00（Asia/Shanghai）**执行：每轮登记并测试一条 `OPEN` 主张，写一轮记录并更新登记表。也可以随时手动执行。

## 新增主张

在 `claims.md` 追加一行，写清：ID、主张原文、来源（哪份文档/哪种流行说法）、可操作化定义、测试方式、状态。不要在已有轮次里改结论；要修正就新开一轮并标注"修正第 N 轮"。

## 与仓库其它部分的关系

- 工具行为契约仍以各 Skill 的 `references/` 和 `tests/` 为准；本目录只做"主张层面的证伪"。
- 与 `docs/validation.md` 的分工：那边记录"实现了什么、验证了什么"，本目录记录"哪些模型/假设被推翻、哪些仍站不住"。

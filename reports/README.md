# reports/ 说明：每日财务快照与数据质量记录

本目录是仓库自带的每日观察记录，不是投资收益记录。

## 生成方式

- 工作流 `.github/workflows/daily-report.yml` 每天 UTC 01:00（北京时间 09:00）运行 `.github/scripts/daily_report.py`，用 AKShare 拉取 20 只代表股的财务与估值字段。
- 每次运行写入一个按北京日期命名的 `YYYY-MM-DD.csv`，并覆盖 `latest.md` 作为阅读入口；2026-10-25 起同时写入 `YYYY-MM-DD.csv.meta.json`，记录生成时间、AKShare 版本、股票池、成功/失败/不完整条数与 `historical_point_in_time: false`。
- `paper/` 下是筛选输入冻结后的模拟观察快照，规则见 [模拟记录说明](../docs/paper-journal.md)。

## 为什么提交进 Git

这些文件是连续的数据可用性与数据缺口证据：哪一天取数失败、哪些字段缺失、口径何时变化，都可以按日期对照。它们用于复核取数链路，不能被解释为策略收益、选股建议或对未来的预测。删除历史文件会同时破坏 `latest.md`、`paper/` 快照与文档中的日期引用。

## CSV 口径与限制

- 读取时先看 `score_status` 与 `decision`，再看 `total`：`partial` / `needs_data` 表示筛选所需字段不全，应先补数，不参与完整记录排序。
- 字段定义以生成脚本为准；旧文件的列随脚本迭代变化，2026-10-25 之前没有 `.meta.json`。分析旧快照时按日期分批，并记录当时的脚本版本，不把不同版本的列直接拼接。
- 股票池固定为 20 只代表股，不是全市场覆盖；财务窗口与估值日按抓取时点确定，不构成严格 point-in-time 历史数据。
- 历史文件保持原样，不回溯改写；如需重跑，另建输出目录，不覆盖已提交快照。

维护与巡检流程见 [维护说明](../docs/maintenance.md)。

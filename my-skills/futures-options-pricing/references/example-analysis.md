# 合成数据走查

本例读取 [example-output.json](example-output.json)，输入为 [example-options.csv](example-options.csv)。全部 6 行报价、期货价格 100、定价日 2026-11-24、到期日 2027-06-30、利率 3% 都是人为构造的**合成数据**（`F=100`、`r=0.03`、`T=218/365`），不是任何交易所的行情或历史报价，也不能用来证明模型有效或策略收益。

## 输出里可直接核对的事实

- 到期天数 218，`T = 218/365 = 0.597260274`，`day_count_basis = "calendar_365"`。
- 看涨 C110：市场价 2.61 反推隐含波动率约 0.2000136，标价落在无套利带内。
- 看涨 C100：市场价 8.46 反推隐含波动率约 0.2799021；看跌 P100：市场价 7.86 反推约 0.2599814。
- 只给波动率的行：C95/P95 用 0.20，P105 用 0.22；这些行 `implied_volatility` 为 `null`、状态为 `not_requested`。
- 平价检查有两条：K=95 与 K=100。K=95 残差约 `-8e-15`（两行同为 0.20 波动率，代数上应≈0）；K=100 残差约 `0.600000000001`，因为两行市场报价本身相差 0.60，而 F=K 使折现远期内在价值为 0。

## 手算核对一：C95 理论价

输入 `F=100`、`K=95`、`T=218/365=0.597260274`、`r=0.03`、`sigma=0.20`：

```text
sqrt(T) = 0.772826160
d1 = (ln(100/95) + 0.5*0.20^2*0.597260274) / (0.20*0.772826160)
   = (0.051293294 + 0.011945205) / 0.154565232 = 0.409137935
d2 = 0.409137935 - 0.154565232 = 0.254572703
N(d1) = 0.658780781, N(d2) = 0.600473428
e^{-rT} = e^{-0.03*0.597260274} = 0.982241761
Call = 0.982241761 * (100*0.658780781 - 95*0.600473428)
     = 0.982241761 * 8.833102442 = 8.676242100
```

与 JSON 的 `C95.model_price` 一致（四舍五入到 6 位为 8.676242）。手工按同一公式可重算；输出中的其他价格用同样步骤。

## 手算核对二：K=100 的平价残差

```text
call_minus_put = 8.460000000000457 - 7.859999999999507 = 0.600000000000950
discounted_forward_intrinsic = e^{-0.03*0.597260274} * (100-100) = 0
residual = 0.600000000000950 - 0 = 0.600000000000950
```

因此 K=100 的平价残差约 0.60，来源是合成报价故意偏离：两行都只给市场价，脚本用各自反推的隐含波动率重新定价，模型价≈市场价。K=95 两行都使用 0.20 波动率，`call_minus_put` 应等于 `e^{-rT}(100-95)=4.911208806`，残差只是浮点误差。二者都说明残差是“价格口径检查”，不是套利信号。

## 如何读这些数字

- `pricing_volatility` 是真正用于定价的波动率；只给市场价格的行使用反推值，所以 `price_difference_vs_market` 接近 0 是复算而非独立理论价。
- 合成示例中 C100 与 P100 的隐含波动率不同（0.2799 与 0.2600），说明同一行权价的看涨/看跌在市场报价不满足平价时不会得到同一个波动率；这既不证明报价错误，也不给出交易方向。
- 希腊字母是单行、单波动率的局部敏感度，不能替代组合压力测试；theta 按自然日/365，不区分交易日。
- 本例没有成交量、买卖价差、保证金、费用、合约乘数或行权方式信息，因此不给出任何下单、套利、目标价或收益结论。

这是对固定公式和固定合成输入的人工核对，不是独立模型评测，也不是市场策略验证。

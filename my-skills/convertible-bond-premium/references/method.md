# 转股溢价、债底与强赎计数方法

本页固定 `scripts/convertible_bond_premium.py` 的记账口径。所有金额以“一张转债”为基准，`face` 缺省 100 元；脚本只做算术，不核对募集说明书、评级报告或交易所公告。示例数字均为便于手算的合成值。

## 符号与现金流时点

- `face`：面值（元/张），缺省 100。
- `conv_price`：转股价（元/股）；`stock_price`：正股价（元/股）。
- `price`：转债价格（元/张）。
- `coupons`：剩余各期票息率（小数），`m = len(coupons)`；留空表示零息。
- `years_left`：剩余年限（年），可为小数。
- `redemption_price`：到期赎回价（元/张），按契约口径**含最后一年利息**。
- `r`：贴现率（每只债可不同）；`y`：到期收益率。
- 票息时点：`t_k = years_left - (m - k)`，`k = 1..m`。因此 `t_m = years_left`，最后一期票息与到期赎回发生在同一时点；`t_k` 是距估值日的年数，不是第 k 个自然年。
- 现金流：第 k 期票息为 `coupon_k × face`，到期另有 `redemption_price`。

时点示例：`m = 4`、`years_left = 4.0` 时 `t = 1.0, 2.0, 3.0, 4.0`；`m = 4`、`years_left = 3.5` 时 `t = 0.5, 1.5, 2.5, 3.5`。折现指数用 `years_left` 与 `t_k` 直接计算，不按自然年对齐，也不做工作日调整。脚本要求全部 `t_k > 0`（即 `years_left > m - 1`）：票息期数多于剩余年限时直接报错退出，而不是用负指数把未来现金流折成更大的现值。这类输入本身说明票息表或剩余年限抄错了，应在整理数据时先修正。

## 转股价值与转股溢价率

公式：

- `conversion_shares = face / conv_price`
- `conversion_value = conversion_shares × stock_price`
- `conversion_premium = price / conversion_value - 1`

手算例：`face = 100`、`conv_price = 12.5`、`stock_price = 11.2`、`price = 104`。

- 转股数 `= 100 / 12.5 = 8.0000000000` 股
- 转股价值 `= 8.0 × 11.2 = 89.6000000000` 元
- 转股溢价率 `= 104 / 89.6 - 1 = 0.1607142857`（即 16.0714%）

溢价率为正表示价格高于按当前正股价折算的转股价值；为负表示折价。它只是价格与转股价值的比值，不含任何对正股未来价格的假设。转股数用面值直接除以转股价得到理论股数，整股取整与不足一股的现金替代未建模。

## 纯债价值（债底）

公式：

`pure_bond_value = Σ_{k=1..m} coupon_k × face / (1+r)^{t_k} + redemption_price / (1+r)^{years_left}`

零息（`coupons` 为空）时只剩赎回价一项，例如 `redemption_price = 100`、`years_left = 1.0`、`r = 0.035` 时 `pure_bond_value = 100 / 1.035 = 96.6183574879` 元。

手算例：`face = 100`、`years_left = 4.0`、`coupons = 0.002|0.004|0.006|0`、`redemption_price = 108`、`r = 0.035`。

- `m = 4`，票息时点 `t = 1.0, 2.0, 3.0, 4.0`
- 票息现金流 `= 0.200, 0.400, 0.600, 0.000` 元
- 折现因子 `1.035, 1.071225, 1.108717875, 1.147523000625`
- 各期现值（10 位小数）`= 0.1932367150, 0.3734042801, 0.5411656234, 0.0000000000`
- 赎回价现值 `= 108 / 1.147523000625 = 94.1157605914` 元
- `pure_bond_value = 95.2235672100` 元（按未舍入的各项求和）

### 到期赎回价的含息口径

`redemption_price` 按契约视为“到期赎回价（含最后一年利息）”，所以最后一期票息通常应写 0；上面例子正是 `coupon_4 = 0`、`redemption_price = 108`。如果赎回价已含末期利息、又写了最后一期票息，脚本会把两者都折现相加：例如把 `coupon_4` 写成 `0.01`（即 1.00 元），纯债价值会多算 `1.00 / 1.147523000625 = 0.8714422277` 元，变成 `96.0950094377` 元。脚本不替用户判断这个口径，填写时需要自己确认。

债底是给定贴现率下的折现结果，不是保本价格，也不是发行人兑付能力的估计。

## 债底溢价率

公式：

`bond_floor_premium = price / pure_bond_value - 1`

手算例：沿用上例 `pure_bond_value = 95.2235672100`，取 `price = 104`：

`104 / 95.2235672100 - 1 = 0.0921666038`（即 9.2167%）

债底溢价率为正，只说明价格高于该贴现口径下的债底；它不说明信用风险高低，也不说明价格“贵”或“便宜”。

## 到期收益率 YTM（二分法）

定义：解

`price = Σ_{k=1..m} coupon_k × face / (1+y)^{t_k} + redemption_price / (1+y)^{years_left}`

右侧是 `y` 的严格递减函数（`y > -1` 时每项分母随 `y` 增大而增大），所以根至多一个。脚本在 `[-0.9999, 10.0]` 内用二分法：每次取中点，按 `PV(mid)` 与 `price` 的大小折半区间，以区间宽度 `1e-12` 为停止容差、最多 400 次迭代；若区间两端同号（无解），`ytm = null` 并附 `ytm_note`。

手算例：`price = 100`、`face = 100`、`years_left = 2.0`、`coupons = 0.02|0`、`redemption_price = 102`。

- 票息时点 `t = 1.0, 2.0`；现金流 `= 2.00`（t=1）、`102.00`（t=2）
- 方程 `100 = 2 / (1+y) + 102 / (1+y)^2`
- 令 `x = 1+y`，得 `100x² - 2x - 102 = 0`
- `x = (2 + √(4 + 40800)) / 200 = (2 + 202) / 200 = 1.02`
- `y = 0.0200000000`（即 2.0000%）

数值校验：`PV(0.01) = 101.9703950593`、`PV(0.03) = 98.0865303045`，根在两者之间；`PV(0.02) = 100.0000000000`。二分法在容差内给出的结果与 0.02 的差不超过 `1e-12` 量级。

YTM 是“按当前价格买入、持有到期、票息与赎回价按期足额收到、不扣税费”的贴现率反解，不是可实现收益，也不代表信用风险已被定价；再投资、赎回/回售等嵌入期权与违约均未建模。

## 双低值

公式（经典定义）：

`double_low = price + 100 × conversion_premium`

系数 100 把小数溢价率换成百分点。手算例：沿用转股例的 `price = 104`、`conversion_premium = 0.1607142857`：

`double_low = 104 + 100 × 0.1607142857 = 120.0714285714`

折价例：`price = 95`、`conversion_premium = -0.05`，则 `double_low = 95 + 100 × (-0.05) = 90.0000000000`。

双低值是价格与溢价率的固定线性组合，不是估值模型；权重 100 是本方法的定义，不是市场共识或最优参数。

## 强赎计数

给定 `trigger_ratio`、`trigger_window`、`trigger_days` 与正股收盘序列：

1. `price_threshold = trigger_ratio × conv_price`。
2. 取该 `code` 按日期升序后的最后 `trigger_window` 个交易日收盘价；只数 CSV 中实际存在的行，不补节假日、不换自然日、不按代码字符串排序。
3. `count = #{close : close >= price_threshold}`，边界含等号。
4. `observed_days` 为实际可用交易日数（不超过 `trigger_window`）。
5. 判定：`observed_days < trigger_window` → `insufficient-history`；否则 `count >= trigger_days` → `triggered`，否则 `below`。无正股 CSV 或无该 code → `no-stock-series`，此时 `count` 与 `observed_days` 为 `null`。

手算例：`conv_price = 10.0`、`trigger_ratio = 1.3`，阈值 `= 13.0000000000`；窗口 5 天、要求 3 天；最后 5 个交易日收盘价为 `12.8, 13.0, 13.4, 12.9, 13.6`。

- 达标：`13.0`（等于阈值，计入）、`13.4`、`13.6`，共 `count = 3`
- `observed_days = 5`，`count >= trigger_days`，结果 `triggered`
- 若只提供 4 天数据，则 `observed_days = 4 < 5`，结果为 `insufficient-history`
- 若没有正股序列，则结果为 `no-stock-series`，`count` 与 `observed_days` 为 `null`

计数只回答“给定窗口与给定收盘序列下，达到阈值的天数是多少”。它不补数据、不判断公告、不判断发行人是否已进入赎回程序，也不处理下修、回售、条款差异与计数起点。

## 浮点、容差与展示

脚本输出保留完整浮点，不做展示性四舍五入；本文示例为便于核对保留 10 位小数，末位可能与实际输出不同。强赎比较使用脚本内的浮点值，边界含等号，但恰在阈值附近的价格仍可能受浮点表示影响，需要确认时由研究者自行核对原始收盘价。
